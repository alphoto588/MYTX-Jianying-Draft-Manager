# 剪映草稿历史版本管理器

一个零依赖的本地小工具：查询剪映专业版草稿的历史版本（`.backup/` 目录），
在网页上列出全部版本，并可一键把任意历史版本恢复为当前草稿。

## 功能

- **扫描草稿**：自动识别剪映草稿根目录（`JianyingPro Drafts`）下的所有草稿项目
- **自动发现根目录**：「🔍 自动发现」扫描常见位置与各盘符；「🔎 深度扫描」遍历盘符兜底非常规位置
- **回收站找回**：自动列出剪映回收站（`.recycle_bin`）中误删的草稿，可像正常草稿一样管理
- **历史版本列表**：解析 `.backup/` 中的 `save / close / load` 备份及恢复快照，
  显示时间、类型、大小、与当前版的差异百分比、MD5
- **一键恢复**：点击「恢复此版本」后自动完成：
  1. 检测剪映是否在运行（运行中则拒绝操作，防止写入冲突）
  2. 把当前 `draft_content.json` 自动备份到 `.backup/`（命名含时间戳，可随时回退）
  3. 用所选版本覆盖 `draft_content.json`
- **备份清理**：一键清理过旧的「自动保存」备份（保留最近 N 个），只清理 save 类型，
  绝不触碰关闭/打开备份、恢复快照和与当前版内容相同的备份
- **单个删除**：版本列表每行都有「删除」按钮，不要的版本直接删掉（不可逆，需确认）
- **类型筛选**：按自动保存 / 关闭备份 / 打开备份 / 恢复快照 / 上一版本快速过滤
- **安全防护**：路径穿越校验、恢复操作加锁、恢复前强制备份

## 启动方式

方式一（推荐）：双击 `start.bat`

方式二（命令行）：

```bash
python app.py            # 默认端口 8620
python app.py --port 9000
```

启动后用浏览器打开 <http://127.0.0.1:8620>

> 必须安装python,版本在 Python 3.8+ 及以上即可，无需安装任何第三方库。

## 使用流程

1. 首先在下载python并安装，默认安装，确保python3.8+版本可用,下载地址：
   - Windows: https://www.python.org/downloads/windows/
2. 启动服务，确认页面顶部显示「剪映未运行 · 可安全恢复」（如显示运行中请先关闭剪映）
3. 根目录会自动发现；如你的草稿在非常规位置，点「🔍 自动发现」或「🔎 深度扫描」，点击结果即可
4. 如知道草稿根目录，建议直接输入根目录路径，点击「扫描草稿」即可
5. 点击草稿卡片，查看「当前草稿版本」和「历史版本列表」
6. 找到想要的版本，点击「恢复此版本」，在确认弹窗中点击确定
7. 重新打开剪映即可加载恢复后的草稿

## 找回误删的草稿

剪映删除草稿时会移入草稿根目录下的 `.recycle_bin`（回收站）。本工具扫描草稿时会自动
列出回收站中的草稿（名称带 🗑 标记，排在最后），可以查看其历史版本并恢复。
确认无误后，把该草稿文件夹从 `.recycle_bin` 移出到根目录（或在剪映中还原）即可正常打开。

## 回退方法

每次恢复前，工具都会把当时的 `draft_content.json` 备份为：

```
<草稿目录>/.backup/YYYYMMDDHHMMSS_restore_<md5前8位>.save.bak
```

如需回退，在列表中找到该「恢复快照」再次点击恢复即可。

## 源码结构速览（app.py）

```
app.py
├─ 常量区            文件名/备份名的正则、各版本类型的标签与配色
├─ 工具函数区        MD5、体积格式化、时间格式化、剪映进程检测
├─ 扫描与发现区      discover_roots（快速/深度扫描）、list_drafts（列出草稿）
├─ 版本管理区        list_versions（列版本）、restore_version（恢复）、
│                    cleanup_backups（清理）、delete_version（删除）、safe_backup_file（防路径穿越）
├─ 前端页面区        INDEX_HTML：单文件内嵌前端（样式 + 脚本）
├─ HTTP 服务区       Handler：/api/state、/api/drafts、/api/discover、
│                    /api/versions、/api/restore、/api/cleanup、/api/delete
└─ 入口              main()：--port / --host 参数，启动 ThreadingHTTPServer
```

安全设计要点：剪映运行中禁止一切写操作；恢复前强制自动备份；
文件名经 `safe_backup_file` 校验，防路径穿越；恢复操作由 `RESTORE_LOCK` 串行化。

## 常见问题

- **找不到草稿根目录？** 点「🔍 自动发现」扫描常见位置和各盘符；仍找不到就用「🔎 深度扫描」遍历盘符兜底（较慢，通常 1 分钟内）。
- **误删的草稿能找回吗？** 能。见上文「找回误删的草稿」。
- **为什么点击「恢复此版本」没有反应？** 页面右上角显示"剪映运行中 · 已锁定恢复"时，所有恢复/清理操作都会被禁止。请先完全关闭剪映（含托盘进程），状态变为绿色后重试。
- **端口被占用怎么办？** 用命令行方式换端口启动，例如 `python app.py --port 9000`，然后访问 `http://127.0.0.1:9000`。

## 注意事项

- 恢复操作务必在**剪映完全关闭**时进行（包括系统托盘中的剪映进程）
- 「删除」按钮**不可逆**：删除的历史版本不会进回收站，删前请确认；删除"恢复快照"将放弃对应的回退机会
- 草稿内容为剪映加密存储，本工具只做文件级版本管理，解密由剪映读取草稿时自动完成
- 恢复后打开剪映，草稿的封面/时长等缓存信息会自动刷新，短暂显示旧信息属正常现象
